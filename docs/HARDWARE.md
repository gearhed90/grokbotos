# 하드웨어, 드라이버, 펌웨어

이 문서는 Fedora bootc 이미지에서 하드웨어를 다루는 전략이다. 여기서 어떤 기기도 부팅해 보지 않았다. 체크리스트의 모든 칸은 미확인이다.

## 커널이 가져오는 것

드라이버의 기본 출처는 이미지 안의 커널이다. `quay.io/fedora/fedora-bootc`의 커널이 그 장치를 지원하면 추가 패키지 없이 동작한다. Intel/AMD GPU, 많은 USB 입력장치, 커널에 올라간 Wi-Fi 컨트롤러가 이쪽이다.

펌웨어의 1차 출처는 그 커널이 의존하는 `linux-firmware`다. 이 저장소에서 fedora-bootc 이미지 안의 패키지 목록을 열어 보지는 않았다. 특정 펌웨어 파일이 들어 있다고 적지 않는다.

## 이미지 빌드 때 넣어야 하는 것

`/usr`는 불변이다. 설치가 끝난 기계에서 `dnf`로 커널 모듈을 깔아도, 다음 bootc 업데이트의 커널과 맞지 않거나 배포에 남지 않는다. 비자유 드라이버와 추가 펌웨어는 이미지를 만들 때 넣는다.

해당하는 것:

- Nvidia처럼 커널 모듈을 따로 빌드해야 하는 GPU. RPM Fusion의 akmods를 이미지 빌드 안에서 그 커널에 맞춰 컴파일한다. 부팅한 뒤 설치하지 않는다.
- `linux-firmware`에 없는 Wi-Fi, 노트북 오디오 펌웨어. 라이선스가 이미지에 다시 배포하는 것을 막으면 넣을 수 없다. 그 경우는 그 기기를 지원 대상에서 뺀다.
- 그 밖의 아웃오브트리 모듈. 같은 규칙이다. 빌드 때 넣고, 런타임에 깔지 않는다.

기본 이미지(`oais`, `oais-arm64`)에는 Nvidia를 넣지 않는다. 넣는 시점은 별도 이미지 변형이다. 이름과 빌드는 아직 없다.

## 처음 맞출 기기

처음 확인할 대상은 Intel 또는 AMD GPU와, 커널과 `linux-firmware`만으로 붙는 Wi-Fi를 쓰는 PC다. 노트북이든 데스크톱이든 같다. Nvidia 전용 이미지는 그 다음이다. Apple Silicon은 이 이미지의 arm64가 아니라 이전부터 쓰던 UTM 가상머신 경로이고, 실기 Mac 하드웨어 지원이 아니다.

## 확인할 때 볼 목록

한 기기에서 아래를 보고, 결과를 매트릭스에 적는다. 하지 않은 항목은 미확인이다. 이전 AI-OS 이미지에서 본 화면을 이 이미지의 확인으로 적지 않는다.

| 항목 | 보는 법 |
|---|---|
| 부팅 | 재부팅 뒤 패널 없이 Grok Bot만 보이는지. 안내 페이지면 RPM이 빠진 빌드다 |
| 디스플레이 | 내장 패널 또는 HDMI에 화면이 나오는지 |
| 입력 | 키보드, 포인터가 sway에서 동작하는지. `Alt+Tab`, `Alt+G` |
| Wi-Fi | 연결되는지. 펌웨어 실패는 `Ctrl+Alt+F2`의 `dmesg` |
| 오디오 | 소리가 나가는지 |
| 절전 | 지원하는 기기만. 깨어난 뒤 화면과 네트워크가 돌아오는지 |
| 이미지 | `bootc status`가 그 아키텍처의 `oais` 또는 `oais-arm64`를 가리키는지 |
| 세션 | 재부팅 뒤 Grok Bot 로그인 상태가 홈에 남는지 |

## 베이스

Fedora bootc를 유지한다. Arch로 바꾸지 않는다. 이미지 파이프라인, ostree 배포, 실패 시 이전 부팅으로 돌아가는 경로가 이미 bootc다. 아래의 로컬 파생 이미지도 그 모델 위에 올린다.

## Grok Bot이 제안하는 드라이버

구현하지 않았다. 시험하지 않았다. 로드맵 Phase G와 같은 내용이다.

사용자가 Grok Bot에게 드라이버나 하드웨어 문제를 말한다. Grok Bot은 `lspci`, `lsusb`, `dmesg`와 커널·펌웨어를 보고, akmods/DKMS 형태의 모듈이나 RPM Fusion/`linux-firmware` 패키지를 고른다. 그 결과를 지금 부팅 중인 이미지를 `FROM`으로 하는 로컬 이미지로 만든다. 커널 헤더와 빌드 도구는 빌드 스테이지에만 둔다. 마지막 레이어에는 모듈이나 펌웨어만 남긴다.

적용은 사용자가 로그를 보고 승인한 뒤에만 한다. 그 다음 `bootc switch` 또는 `bootc upgrade`와 재부팅이다. 첫 부팅의 systemd 건강 확인이 화면, 네트워크, Grok Bot 시작을 제한 시간 안에 본다. 실패하면 `bootc rollback`으로 이전 배포에 돌아가고, 배포가 아예 안 올라오면 부트 카운터가 이전 항목을 고른다. 성공하면 그 배포를 유지한다.

만든 모듈은 출처를 로그에 남기고, 서명 없이 조용히 신뢰하지 않는다. Secure Boot가 켜져 있으면 서명 없는 모듈은 올라가지 않는다. MOK 등록은 사용자가 보는 단계다. Secure Boot를 자동으로 끄지 않는다. 승인 없는 적용은 없다.

## 호환 매트릭스

아직 표가 없다. 행은 기기(모델, CPU, GPU, Wi-Fi), 열은 위 항목, 칸은 확인 / 실패 / 미확인이다. 실패에는 커널 버전과 `dmesg`에서 본 펌웨어 이름만 적는다. 기기를 구하기 전에는 행을 만들지 않는다.
